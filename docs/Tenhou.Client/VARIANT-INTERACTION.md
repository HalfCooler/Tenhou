# 四川、国标牌桌交互草案

状态：设计建议，尚未实现图形交互。基于当前仓库的 `VariantTableView`、`VSTATE/VACT` 和服务端规则检查。

## 当前已有的能力

- `variant_table_view.cpp` 显示四家手牌文字、牌河、副露、花牌和分数，操作列表可双击或选中后执行。已有最小可用操作链路，缺的是直接操作牌面的体验。
- `network_protocol.cpp` 已把服务端 `actions` 转成 `OnlineAction` 和 `VACT` 消息，并维护动作 revision 和 pending。
- 服务器已实现四川换三张、定缺、血战和牌退场并继续其余玩家对局，及国标自动补花、八番起和。客户端只呈现服务器授予的动作。
- `TableArtwork`、背景、阴影、缓冲绘制、音效库可以复用。`OnlineTable` 的状态投影和 HUD 绑定立直语义，不宜直接把变体数据塞进其中。

## 玩家看到的牌桌

采用四面牌桌：自己始终在下方，其他玩家按相对座位排列；中央显示轮到谁、剩余牌数、盘数和倒计时。自己手牌横排、牌河位于各家内侧，副露靠外。底部右侧放当前合法的吃、碰、杠、和、过按钮，结算和历史可展开查看。

第一版先做平面牌桌和静态牌面。优先把点击、选择、提交、等待和重连做完整，再接动画。现有协议只提供余牌数，不足以重建精确牌墙及摸牌位置；此时显示数字余牌即可。

| 阶段 | 玩家交互 | 提交与反馈 |
| --- | --- | --- |
| 四川换三张 | 单击牌面选中/取消，牌向上抬起；显示“已选 2/3”。首张选定后，仅允许能与当前选择组成服务端合法组合的候选牌 | 选满三张后显示确认按钮；保留修改机会。只匹配服务器下发的 `exchange` 组合，提交后锁定并显示等待 |
| 四川定缺 | 三个大按钮：万、筒、索。手牌显示各门数量，点击后预选，确认提交 | 使用服务端 `dingque` 选项；其他玩家的定缺在服务器公开后再展示 |
| 自己出牌 | 悬停抬牌；单击选中，双击同一张确认打出。非法牌变暗但仍能查看 | 以实体牌 ID 匹配 `discard`；提交后立即禁用输入，等待权威快照，不提前删除本地手牌 |
| 吃、碰、杠 | 显示有合法选项的动作按钮。只有一种组合时直接提交；多种组合展开小牌组供选择 | 每个小牌组保存原始动作索引和 revision；杠区分明杠、暗杠、补杠 |
| 和牌 | 显示“胡”或“自摸”，旁边保留“过” | 是否可和及是否够番均由服务端决定；按钮不自行用客户端算番开关 |
| 四川和牌后 | 展示本次分数变化、和牌和“本手退场”标记，然后回到牌桌等待本局结束 | 血战单次和牌不弹出阻塞整盘的“下一盘”窗口；已和者无合法动作，其余玩家继续 |
| 国标补花 | 花牌进入独立花区，补牌后继续显示手牌；花区支持数量多时换行 | 现有规则自动补花，不新增“补花”操作按钮；花牌不进入出牌选项 |
| 盘结束 | 展示本盘结果和分数；四川显示查花猪、查大叫、退税结果，国标显示服务端算番结果 | 只有 `ended` 进入下一盘确认；`complete` 展示整场结果和返回大厅 |
| 断线、暂停、恢复 | 清除悬停与未提交选择，显示暂停或恢复提示 | pending 或 recovering 时所有提交入口统一禁用；恢复后直接重建当前牌桌 |

四川定缺牌可以加花色角标，出牌时只突出当前合法牌。已和玩家显示“已和退场”，不显示回合标记；该玩家不再摸打或付款。国标的花牌区和圈风、门风使用专用 HUD；两种玩法都不显示立直点棒、宝牌、振听或红宝牌。

## 代码怎么接

### 1. 建立有类型的变体状态

新增 `variant_state.hpp/.cpp`，集中解析 `variant_state` 字符串字段，输出 `VariantState`、四家 `VariantPlayer` 和阶段枚举。统一验证牌 ID、座位、数字和分隔字段，绘制层不再到处 `stoi`。

- 服务器绝对座位转换成相对座位：`(absolute - local + 4) % 4`，自己固定为 0。
- 对手暗牌按 `hiddenN` 生成背面，绝不根据别人的副露或牌河推测手牌实体。
- `0..135` 使用现有牌面资源，四川、国标调用时禁用红五映射。
- `136..143` 单独作为花牌类型。当前 `TileVariant` 对大于 135 的 ID 返回背面，不能直接沿用；先用带文字的花牌面绘制，之后再通过资源清单登记正式图片。
- `winningN`、`winsN`、`missingN`、`flowersN` 保留为独立显示数据，不能映射成立直的 winners、nuki 或 reach。

### 2. 先修动作数据，再做点击

当前 VSTATE 分支把实体牌列表拼在 `OnlineAction.label` 和消息中，`OnlineAction.tiles` 留空。图形交互前应把参数正规解析出来，显示文字不参与动作识别。

`dingque` 参数是花色编号，不是牌 ID，应有专用字段或明确的变体动作参数类型。其他牌组保持实体牌 ID，不能因同牌面就去重成 34 类牌。绘制命中、选中状态与提交均使用实体 ID，提交仍用原始 action index + revision。

新增 `VariantInteraction` 控制器负责悬停、选牌、分组和动作匹配；`VariantTableView` 负责窗口事件与渲染。先保留现有操作列表作为可折叠入口，方便键盘操作和排查问题。

换三张可从服务端所有合法组合中筛出包含当前选择的组合，候选牌取这些组合的并集。这样同花色、实体数量等限制都与服务端保持一致。选牌集合应排序后比较，提交时保留对应服务端动作索引。

输入按下时记录 revision，抬起或双击提交时复核。新快照改变 revision、换盘或暂停时清理选择，防止鼠标停在原位置却提交下一窗口的动作。同样的检查覆盖按钮、键盘和双击三个入口。

### 3. 共用渲染基础，保留玩法 HUD

从当前牌桌提取牌面绘制、布局和命中矩形等通用能力，建立 `VariantTableScene`。继续复用 `TableArtwork`、`PaintBuffer`、阴影和偏好设置，不复制资源解码逻辑。四川和国标可以共用手牌/牌河/副露布局，通过玩法呈现配置启用定缺区、花区和胡牌记录。

不要为了复用现有立直窗口而构造假 INIT、REACH 或 AGARI；特别是四川一次和牌不等于本盘结束。每种玩法决定自己的阶段切换，公共组件只消费呈现数据。

### 4. 动画和音效需要明确的公共事件

现有 VSTATE 适合静态交互，但不足以无歧义复原所有动画：

- 没有独立的摸牌实体字段，不能稳定区分新摸牌和手牌排序变化。
- 副露只有 `kind:tiles`，缺少来源座位及被鸣实体，无法可靠决定横放方向。
- 牌河已过滤被鸣走的牌；完整快照也可能同时包含出牌、副露、补花等多步变化。
- `history` 是最近若干条文字，不是唯一事件 ID；依赖它播放音效会在恢复时重复播报。

建议在保持现有快照和合法动作机制的基础上，增加公共呈现事件：单调递增 `seq`、`kind`、`actor`、可公开的牌和来源，以及当前玩家可见的 `drawn` 字段。首次连接/恢复使用快照对齐到 seq，之后只呈现未处理过的事件；序号缺口走快照重同步。序号、事件及快照的关联需要由服务端明确保证，避免重发和重连重复播放。

先接已有摸打、碰杠、和牌音效，统一经过 `ReplaySoundBank` 和音效音量；换三张、定缺、补花如无合适资源先用通用提示音。当前音频资源是立直客户端语音，不应当作已有四川方言或国标专用语音。私有摸牌事件只给当前视角，其他玩家只收到数量变化。

计分明细后续也应输出结构化条目：玩家、支付者/收款者、分值、番种和原因，覆盖四川各家和牌与盘末结算。第一版可用现有 result/history 展示文字，不在客户端重新推导规则。

## 推荐实施顺序与完成标准

1. **可直接点击打牌**：有类型快照、实体动作参数、四面静态牌桌、合法出牌高亮、点击与按钮提交。用两种玩法真实服务端状态完成一盘，并覆盖暂停、重复点击和旧 revision。
2. **玩法专用阶段**：四川按局序换牌/定缺/和牌退场；国标花区/补花/吃牌组合；两种结算。测试数据包含重复牌面、仅一个可选组合、多个吃/杠组合、其他三家定缺尚未公开。
3. **呈现事件与质感**：补充事件身份和来源，接动画、音效、分数变化。验证同一事件只播放一次、恢复不重播、跳帧不会阻塞提交期限。

现有 `variant_ui_check.cpp` 的离屏截图可扩展为 exchange、missing、turn、claims、ended、complete 六类场景；输入控制器另做实体选中和 revision 测试。现有原生协议检查继续验证 VACT 提交和两种规则能跑完整场。图形窗口仍需实际点击验收，静态截图不代表交互已经通过。
