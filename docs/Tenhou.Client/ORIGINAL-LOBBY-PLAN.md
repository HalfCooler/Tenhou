- **中文化**：原始代码中用于显示的日文字符串在重建端译成中文，进入现有文字目录，覆盖页签、菜单、资格、按钮、状态、错误和规则说明。首批用语：`段位戦` → 排位战，`上級／鳳凰` → 上级／凤凰，`予約／参加登録` → 预约／报名参赛，`東風戦／東南戦` → 东风战／东南战，`紅天β／東天紅` → 东天红 β／东天红。调查证据保留原文；协议字段、命令、存档键、类型值和标识符不翻译，大会自定义标题与玩家名不是固定 UI 字符串。

## 二、预约、切厅与大会

- **格位、玩法、资格是三件事。** `FUN_0043f590` 的四卓掩码依次 `0x00 / 0x80 / 0x20 / 0xA0`。东风／东南候选基础 type：喰断なし `7/15`、通常赤 `1/9`、速 `0x41/0x49`、光 `0x1041/0x1049`、三麻赤 `0x11/0x19`、三麻速 `0x51/0x59`，与卓掩码按位或。`1` 是通常赤东风所落入的默认分支；不得把未知控件也映射为合法队列。`0x4F8DA0` 的页签提示依次为 `四段R1800未満`、`１級以上+有`、`四段R1800以上`、`七段R2000以上`；右栏明确鳳凰为付费会员限定、上級可覆盖低于一级的付费会员。它们是原版文案，不代替门槛判定；按四人／三人独立资格验证临界值及各格显隐。
- **预约可跨卓并存。** 点击发送 `<JOIN t="房号,玩法type" />`，排名战房号为 `0`；`LN` 解析 `n/j/g` 数组，格旁显示 `预约:对局中`。取消路径发送空 `<JOIN />`；重入分支有 `REJOIN_ALL` 和逐项重发；`LOBBY_LASTTAB` 保留外层及子页选择。官方天鳳《マニュアル》的ロビー说明也确认跨四卓多选、先凑齐者开桌。切子页不发换厅命令，不清其他预约；计数不用于确认本人预约。待锁定 `LN` 槽位索引及确认/重发时序，再模拟取消与开桌交叉。
- **切厅不等于预约。** 菜单含排名战、事件会场 1–3、编号指定与历史入口；排名／私室路径发 `CHAT text="%2Flobby%20…"`，大会路径发 `<CS lobby="C%08d" />`。大会确认解析拆为前后各四位；重建保留整个字符串与前导零，以服务端确认驱动页面切换。在失败或超时后留在已确认房间，不能把报名、入场和预约当成一个操作。
- **大会由配置驱动。** 原版解析 `title / players / premiumonly / joinfee / rule / csrule / join`，有 `CSREG FAILED` 分支；其取值、约束和确认顺序要用夹具复核。第一版交付单一大会规则、资格及预约，不套用段位矩阵，不更改段位/R，不做真实收费；之后按赛事配置扩展多赛制、积分榜和固定桌等可选功能，不把它们当作每场大会必选项。
- **大会复用底板，但替换内容。** `FUN_0043f310` 的大会分支切到非排名外层栏 `対戦||||観戦|牌譜|ﾍﾙﾌﾟ`；标题格式是 `大会C%04d`，而 `LOBBY_LAST` 保存完整 `C%04d%04d`。左侧有 `WC_WWW` 内容控件（初始 `about:blank`）；`予約`（`0xFBB`）与 `参加登録`（`0xFBC`）共享主区内 `(180,186)`，由状态控制显隐，不做成并排动作。右栏规则在白底 DIB 上用 `DrawTextW` 自动换行。切厅还会设置 5 秒定时器并触发初次刷新；不把这等同于每 5 秒都发送 `<DATE />`。证据：`tenhou.exe.c:38293` / `:39033`，`tenhou.exe.txt:100543` / `:100622` / `:101627`；显示标题与按钮文案见 PE `004F8DEC` / `004F8B10`。

定位：原版 `tenhou.exe.c:31628`、`:31789`、`:31982`、`:38755`、`:39137`；`tenhou.exe.txt:98789`（预约实发）、`:99319`（CSREG 失败）、`:101702`（大会配置）、`:102602`（房号解析）、`:103008`（重入）。官方文档只用于核对公开行为，不覆盖历史 EXE 字段。

## 三、東天紅：实验入口和实际牌桌差异

| 确认项 | 证据与影响 |
| --- | --- |
| 两个入口 | `GetFileAttributesA("toutenkou.test")` 成功时显示 `紅天β`。面板 `0xFA9` 首格 `0xFAF` 写作 `三紅６`，发送 `JOIN` 的 type `0x811`（`0x800` 特殊玩法 + `0x10` 三人 + 基础位）。另有 `ﾃｽﾄﾌﾟﾚｲ` 菜单项 `東天紅 ３局 サンマβ`，命令 ID `0x874`，走另一处理路径。菜单命令 ID 不等于预约 type；按钮存在不代表当前官方后端接受。 |
| 牌山与动作 | 牌山映射使用 112 张而非普通三麻的 108 张。特殊拔牌路径查找实体 ID `0–3 / 16–19 / 32–35 / 120–123`（`1m / 5m / 9m / 北`），构造带 ID 的 `n%d` 候选。需覆盖多张候选、每家公开拔牌、恢复和回放；不能沿用只拔北的限制。112 张不能单独证明拔后从哪端补牌或是否摸尽。 |
| 标识与结算 | `588` 是 `東天紅` 标题；`mask & 0x800` 时结算用 `点`（564）替换 `飜`（562），另一数栏使用 `枚`（565）；多条项目的布局调整，并跳过常规 `FUN_004afb40` 结算子区。要为 `点/枚` 保留独立单位，不复用普通立直的符番计算；数据量纲、分页和项目顺序须用结算夹具确认。 |

定位：原版 `tenhou.exe.c:31520`（开关）、`:33207`（格位）、`:94455` / `:97537`（牌山）、`:99009` / `:99875`（拔牌候选）、`:119573` / `:120584`（结算）；`tenhou.exe.txt:98789` / `:98864`（两入口）。

**尚不能承诺规则等价。** 优先取证：六赤分布，拔牌是否强制及例外，补牌/抢拔/杠/宝牌/末墙，立直/振听/和牌优先级，点与枚的算法、支付与供托，以及试打「３局」和预约模式的轮庄、流局和终局。同名雀庄规则不是天鳳实验规则的替代来源。证据不足时只交付入口占位和显式开启的开发夹具，不把它作为可玩的正式玩法开放。

## 四、实施顺序与验收门槛

| 阶段 | 交付与门槛 |
