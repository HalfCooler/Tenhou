## 登录入口与菜单

- 原版登录提交分支在 `0x4A50AD–0x4A5134` 检查 `ID` 前缀、19 个字符及半角字母、数字和连字符，再构造登录消息。重建端另外固定连字符位置和两侧长度。保留当前校验。原版 `NoName` 和既有注册账号均已进入官方大厅，新建账号及登录失败仍待核对。 [官方会话](ORIGIN-STAGE3.md)
- 排位场的外层页签是 `段位戦`、`雀荘β`、`観戦`、`牌譜`、`ﾍﾙﾌﾟ`（帮助）。存在 `toutenkou.test` 时多出 `紅天β`。非排名场的外层首项为 `対戦`。证据见 `tenhou.exe.c:31520–31528` 和 PE 文案 `0x4F7090 / 0x4F70A8 / 0x4F70C8`。
- 底部依次为菜单 `0xFBE`、试打 `0xFBD`、取消 `0x2`，创建见 `tenhou.exe.c:31506–31517`。菜单的「ロビーの移動」包含排名战、事件会场 1–3、配信部屋 β、历史房间、编辑和编号指定。主菜单另有牌谱解析脚本、打开牌谱／观战 URL、打开牌谱文件、显示、设置、付费及登出。菜单构造和命令分派见 `tenhou.exe.c:31651–31864`。试打的普通立直、雀庄与东天红应各自核对入口和启动结果。
- 观战和牌谱的入口及链接可参考 `tenhou.exe.c:33383` 附近的 `WC_LOBBY_WG / WC_WWW` 和原版的 `?wg=`、`?log=` 路由。排位、大会、观战、牌谱、帮助及菜单各命令应分别验证，现有本地牌谱、显示和设置可作为接入点。

## 对战大厅

`WC_LOBBY` 在父客户区居中，主内容可见时用 GDI+ 绘制底板 592（`0x426DF3`）。原版逻辑坐标中，左栏的标题、连接状态、外层页签和主区分别从 `(30,45)`、`(30,75)`、`(30,95)`、`(30,120)` 开始，主区为 290×230。创建路径见 `tenhou.exe.c:31490–31517`。状态行的「接続」由大厅初始化代码设置，预约状态另走格位和取消分支。

### 排位格位、资格与预约

一般、上级、特上、凤凰是排位大厅 `L0000` 的四个子页签，页号 `p=0..3`。四页共用两列东风／东南和六行候选格。每格有独立的预约控件，计数显示使用 `LN` 中的 `j/g` 数组。以下每对值按东风／东南排列，槽位从 0 起算。

| 候选行 | 控件 ID | 基础 type | `j/g` 槽 |
| --- | --- | --- | --- |
| 四麻无食断 | `0xFAF / 0xFB0` | `0x7 / 0xF` | `16p+3 / 16p+7` |
| 四麻食断赤 | `0xFB1 / 0xFB2` | `0x1 / 0x9` | `16p / 16p+4` |
| 四麻食断赤速 | `0xFB3 / 0xFB4` | `0x41 / 0x49` | `16p+8 / 16p+12` |
| 四麻食断赤光 | `0xFB5 / 0xFB6` | `0x1041 / 0x1049` | `16p+9 / 16p+13` |
| 三麻食断赤 | `0xFB7 / 0xFB8` | `0x11 / 0x19` | `64+2p / 65+2p` |
| 三麻食断赤速 | `0xFB9 / 0xFBA` | `0x51 / 0x59` | `72+2p / 73+2p` |

- 基础 type 分别按位或各卓的 `0x00 / 0x80 / 0x20 / 0xA0`（`0x43F590`）。计数向量在绘制侧按 `n/j/g = 4/113/113` 处理（`tenhou.exe.c:32919`），页头使用 `n[0]、n[2]、n[3]`，雀庄 β 使用 `j/g[96..103]`，东天红首格使用 `j/g[112]`。本人预约状态独立维护。
- `0x439D81` 的已回放状态按四麻、三麻分别取段位和 R。设 `S = 段位码 ≥ 13 且 R ≥ 1800`、`P = 段位码 ≥ 16 且 R ≥ 2000`，一般显隐用 `!S`，上级用 `(段位码 ≥ 9 或会员数值 ≥ 60) 且 !P`，特上用 `S`，凤凰用 `P`。上级比较的是预约面板 `[EBX+0x8]`（`0x439F5E`）。读入 `HELO` 时，先按 `expire` 是否非空置为 0 或 1，若有 `expiredays` 再用它的数值覆盖（`0x43E42F–0x43E49E`）。四麻光另需 `opt & (1 << p)`，已有预约的格位可见但禁用。官方注册会话样本显示一般／上级预约格和特上／凤凰资格提示，服务端实际预约准入待验证。 [注册账号实窗](ORIGIN-STAGE3.md#官方注册账号会话)
- `0x43AF7D` 发 `<JOIN t="0,type" />` 并维护跨页预约位集，`0x43E6CD` 可逐项重发，`0x42706F` 发送空 `<JOIN />` 取消。房间 ID 与玩法 type 都要参与预约标识。取消、迟到回复、首次开桌和重连的竞态待端到端验证。

### 切厅与大会

- 切厅分为普通房间的 `CHAT text="%2Flobby%20…"` 和大会的 `<CS lobby="Cxxxxxxxx" />`（`0x43E608`）。回放确认入站 `CHAT lobby` 驱动房间切换（`0x43E076`），应保存完整大会 ID 和前导零。`CS` 配置与已确认会场分别处理。
- 大会解析 `title/players/premiumonly/joinfee/rule/csrule/join`（`0x43D3EB`）。报名 `0xFBC` 和预约 `0xFBB` 共用主区内的 `(180,186)`，回放覆盖被挡、需报名、开赛前、可预约、截止与已预约。已报名的可预约区间为 `[开始, 截止)`。`CSREG FAILED` 是报名失败分支（`0x43B5ED`）。官方 `C00112233` 的访客和注册样本均先收 `CHAT lobby` 再收 `CS`，`join` 分别为 0 和 1，两次实窗均显示会员限定及会期结束。开放会期的准入拒绝、报名、费用及开桌返回待核对。 [官方会场回包](ORIGIN-STAGE3.md)

### 右栏资料与规则

- `WC_LOBBY_PROF`（`0xFA2`）与 `WC_LOBBY_RULE`（`0xFA3`）共用 `(320,30,240,370)`，见 `tenhou.exe.c:31500–31503`。截图显示玩家名和会员有效期，原版资料窗由 `0x42A1E0` 转到 `0x42A510` 处理。`0x42A6DE–0x42A734` 创建两个 `WC_ITEM_BTN`，全期间 `0xFC0` 和月间 `0xFC1`，原文在 `0x4F7E54 / 0x4F7E4C`，相对资料窗锚点为 `(15,30)` 和 `(15,165)`，宽度均为 220。实窗确认右上角独立按钮 `0xE104` 的菜单为「テキストで表示」「画像を保存」，命令分别为 `0xFC2 / 0xFC3`。
- `tenhou.exe.c:32279–32292` 把 `HELO` 同时转给资料和预约面板，把 `RANK` 转给资料面板（消息 `0x8209`）。资料窗有 `RANK v2` 处理、`STATUS/PROF_LASTTAB` 选择记忆和 `HELO expire` 的八字符读入分支（`0x432503`、`0x42A598`、`0x43245F–0x4324AA`）。预约面板另读 `HELO PF4/PF3`（`0x43E276 / 0x43E2FF`），会员日期和用于格位显隐的数值应分别追踪。官方注册实窗验证四麻／三麻全期间切换、月间横杠、`PXR V/v` 的部分类型值与重启后的选择恢复。非空月间字段和加载状态待核对。 [注册账号统计](ORIGIN-STAGE3.md#官方注册账号会话)
- 排位规则栏根据预约控件的 `BTN_SETCAPTURE` 切换。未显示规则时设 `0x66` 定时器 500 ms，已显示则立即刷新。释放后清 `0x66` 并设 `0x67` 定时器 500 ms，再切回资料（`0x43C7E6`、`0x43C878`）。原版官方注册排位会话和回环实窗均观察到首次进入、跨格直刷和移出恢复。官方 8141 普通房悬停仍显示资料。

## 东天红与其余入口

东天红有独立试打命令 `0x874` 和受文件开关控制的 `紅天β` 预约（首格 type `0x811`）。原版实窗试打的玩法 type 为 `0x810`。静态证据定位了 112 张牌山呈现、赤牌实体映射及 `点／枚` 结算，`0x49727E` 分支回放确认 1 万、5 万、9 万和北的实体牌能产生拔牌候选。试打实测九万和赤五万拔牌补摸、三局流局和终局返回。全山实体、和牌及有点数变动的结算、完整牌谱和正式桌恢复待验。重建端 `online_game.cpp:119`、`replay.cpp:297` 继续拦截该特殊三麻。雀庄 β、观战、帮助、付费和其他下游菜单应分别取证后确定交付范围。 [东天红原版证据](ORIGIN-STAGE4.md#原版实窗和静态取证)

东天红玩法暂时留下入口，不作实现。

## 离线大厅交付

在仓库根目录运行以下命令。夹具入口使用独立配置目录，页面显示「离线夹具」。

```powershell
.\Build-Tenhou.ps1 -Target Tenhou.Client
.\build\Tenhou.Client\tenhou_rebuild.exe --offline-lobby --config-dir .\build\offline-lobby-demo
```

- `OfflineLobby` 保存已确认会场、待确认目标、大会配置、格位映射、计数、预约集合和资料。预约键为会场完整 ID 与玩法 type。夹具以 250 ms 模拟切厅确认，每秒刷新计数和大会状态。指定编号接受 `0`、四位普通房号或 `C` 加八位大会编号。未知大会显示夹具缺失提示，保留已确认会场。
- 三个活动会场使用原菜单对应的 `C00112233`、`C00223344`、`C00334455`。夹具分别演示报名后预约、首次进入 10 秒后开放且 40 秒后截止、资格拒绝。会场一模拟费用和报名，无实际扣费。显示的身份、段位、成绩和计数均为合成数据。
- Windows 窗口复用发布包图 592、背景构图、缓冲绘制、文字目录及 BGM 播放器。预约后对应格位、菜单和试打按钮禁用，可以继续跨段位页预约，取消按钮或 Esc 清除预约。右栏含全期间和月间资料，停留在可预约格上 500 ms 展示规则，移出 500 ms 回到资料。大厅菜单可切厅、打开本地牌谱、进入设置、最小化和登出。
- 雀庄 β 和可选红天 β 显示格位与合成计数；`--config-dir` 下有 `toutenkou.test` 时显示红天 β。观战、线上牌谱、试打及其他尚待取证的下游功能保留入口。右栏资料字段和规则摘要采用离线样本，原版资料下拉菜单的完整选项和线上字段语义仍待核对。

## 自建服务闭环交付

使用隔离数据目录在本机运行。以下配置演示报名大会、启动后 60 至 180 秒开放的限时大会，以及会员大会。服务器校验 `id`、标准立直 `type` 和时间区间；开始和截止使用 ISO 8601。实际项目可按需要配置 `contests`，缺省时大会菜单中的未配置会场会返回拒绝。

```powershell
.\Build-Tenhou.ps1 -Target Tenhou.Server
.\Build-Tenhou.ps1 -Target Tenhou.Client
$start = [DateTimeOffset]::UtcNow
@{
    listen = '127.0.0.1'
    port = 10081
    dataDirectory = 'service-lobby-data'
    contests = @(
        @{ id = 'C00112233'; title = '报名大会'; type = 9; joinFee = 10
           startsAt = $start.ToString('o'); endsAt = $start.AddHours(2).ToString('o') }
        @{ id = 'C00223344'; title = '限时大会'; type = 17
           startsAt = $start.AddSeconds(60).ToString('o'); endsAt = $start.AddSeconds(180).ToString('o') }
        @{ id = 'C00334455'; title = '会员大会'; type = 1; premiumOnly = $true
           startsAt = $start.ToString('o'); endsAt = $start.AddHours(2).ToString('o') }
    )
} | ConvertTo-Json -Depth 4 | Set-Content -Encoding UTF8 .\build\service-lobby.json
dotnet .\build\Tenhou.Server\Tenhou.Server.dll --config .\build\service-lobby.json
```

在另一个终端启动客户端，每个窗口使用独立的 `--config-dir`。在欢迎页选「第三方服务器」，输入本机地址和端口 `10081`。段位战用各自的注册账号；普通编号场和免费开放大会也可用独立访客会话。各席预约同一会场的同一玩法后开桌。

```powershell
.\build\Tenhou.Client\tenhou_rebuild.exe --service-lobby --config-dir .\build\service-lobby-seat1
```

- 服务独立校验三麻和四麻各自的段位及 R。食断、赤牌和速桌映射到现有立直选项，东风／东南沿用现有计分与结算。光桌保留原版格位定义，开放仍需核对对局行为。只有 `L0000` 的注册真人桌计入段位。大会报名以完整会场 ID 和开赛时间记录，费用字段用于演示。
- 切厅确认、预约和计数均由服务下发。客户端按会场 ID 和代次过滤旧回包；服务器在同一个事件循环中决定取消、开桌或截止的先后。断线期间预约不参与匹配，同一服务进程中重登可恢复仍有效的预约。已入座玩家通过现有存档恢复，结算后回到原会场。
- 线上资料栏显示服务生成的全期间段位、积分、R、场次与名次。样本里的和率、副露率、月间统计等目前没有对应的服务字段。协议细节见 [自建服务大厅协议](../Tenhou.Server/PROTOCOL.md#自建服务大厅)。
