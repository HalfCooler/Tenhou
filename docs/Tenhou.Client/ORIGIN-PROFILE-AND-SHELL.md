## 1. 大厅右侧个人战绩面板（`WC_LOBBY_PROF`）

### 1.1 面板尺寸与子控件

- 面板坐标系：客户端 1x 基准下 `WC_LOBBY_PROF` 位于 `(320, 30)`，宽 `240`、高 `370`（高分辨率下随 `600x430` 大厅壳层等比缩放）。
- `WM_CREATE`（`tenhou.exe.txt` `0x0042a6d1–0x0042a79c`）：创建三个 `WC_ITEM_BTN` 子控件：
  - `0x0fc0`（全期间下拉按钮）：面板内 `(15, 30)`，宽 `220`，对应重建端大厅坐标 `{335, 60, 555, 80}`。
  - `0x0fc1`（月间下拉按钮）：面板内 `(15, 165)`，宽 `220`，对应重建端大厅坐标 `{335, 195, 555, 215}`。
  - `0x0e104`（右上角导出下拉按钮）：空标题、样式 `0x54000006`；`WC_ITEM_BTN` 尺寸计算（`tenhou.exe.c:113020–113041`）在空文本下固定为 `17x10`，`MoveWindow` 置于面板 `x = 0xeb - 17 = 218, y = 0`，对应重建端大厅坐标 `{538, 30, 555, 40}`。点击后弹出菜单：复制文本 / 保存 PNG 截图。
- 按钮文字前缀与样式：全期间／月间下拉按钮标题以 `■` 开头，右侧绘制小下三角箭头，底色为原版浅灰渐变，边框 `#808080`（按下／聚焦时蓝框）。

### 1.2 顶部账号与有效期

- 证据位置：`tenhou.exe.txt` `0x0042a965–0x0042aa60`
- 区域：面板内 `{15, 0, 235, 30}`（大厅 `{335, 30, 555, 60}`），黑色 `DrawTextW(..., DT_CENTER | DT_NOPREFIX)` 两行居中绘制：
  - 第 1 行：账号名（如 `HalfCool`）
  - 第 2 行：`有效期限 : YYYY/MM/DD`（8 位数字 `expire` 按 `%04d/%02d/%02d` 拆分；无有效期或无效时显示 `----/--/--`）

### 1.3 全期间区域（Lifetime）

- 证据位置：`tenhou.exe.txt` `0x0042b1ed–0x0042c2be`
- 段位／pt／Rate 摘要行：居中绘制在 `y = 85`（面板 `y = 55`），行高 `cy = 12`，下划线画在 `y = 85 + cy = 97`（颜色 `#cccccc`，`x = 335..555`）。
  - 琥珀厅（`type & 0x200`）按原版绘制 `R` 与 `G` 摘要（含千分位或原值）。
- 3 列 14 项网格：起始 `grid_top = 85 + cy + 9 = 106`，行步进 `cy + 5 = 17`，下划线画在每项文字底边 `row_y + cy`。
  - 第 0 列：`x = 335`, `w = 57`（`335..392`），5 行：`1位率`、`2位率`、`3位率`、`4位率`、`击飞率`
  - 第 1 列：`x = 402`, `w = 81`（`402..483`），5 行：`对战数`、`平均得点`、`平均顺位`、`平均收支`、`平均祝仪`
  - 第 2 列：`x = 493`, `w = 62`（`493..555`），4 行：`和了率`、`放铳率`、`副露率`、`立直率`
  - 列间留白严格为 `10px`（`392→402`、`483→493`），消除先前重建版本 `1px` 贴边导致的拥挤。
- 禁用灰显行（颜色 `#aaaaaa`，值固定 `-`）：
  - 3 人麻将时 `4位率` 灰显。
  - 非琥珀厅（`(game_type & 0x200) == 0`）时 `平均收支`、`平均祝仪` 灰显。

### 1.4 数值格式化规则

- 证据位置：`FUN_00434290`、`FUN_00434650`、`FUN_004346b0`（`tenhou.exe.txt`）
- 截断而非四舍五入：以 `%f` 展开后按小数点切分并截断至指定小数位。
- 比率格式化（`FormatRate`）：
  - `>= 1.0` 显示 `1.00`
  - `0.0 < v < 1.0` 去掉整数位的 `0`，保留 3 位小数（如 `.279`、`.000`）
  - 零对局或无数据时显示 `-`
- 带符号自适应小数（`FormatSignedAdaptive`）：
  - 正数加 `+` 前缀，负数加 `-`
  - 按整数部分绝对值决定小数位：`< 10` 用 2 位、`< 100` 用 1 位、`>= 100` 用 0 位，并受该字段 `max_decimals` 上限约束（例如月间通算得点上限 0 位得 `+104`，月间平均得点上限 2 位、整数 `52` 得 `+52.0`）。

### 1.5 月间区域（Monthly）与 `RANKING v2` 协议字段

- 证据位置：`tenhou.exe.txt` `0x0042cd56–0x0042db30`、`.rdata` 坐标表 `0x004e58f4–0x004e5998`、`FUN_00433e00`
- `<RANKING v2="...">` 逗号分隔整数数组包含 15 项（普通桌）或 21 项（琥珀／祝仪桌）：
  - `v2[0..3]`：1～4 位次数（`place_counts[0..3]`）
  - `v2[4]`：通算得点（`total_score`）
  - `v2[5]`：预留空位
  - `v2[6..14]`：9 项月间排名 `monthly_ranks[0..8]`，依次为：`综合`、`通算得点`、`平均得点`、`通算顺位`、`平均顺位`、`一位率`、`连对率`、`末位率`、`Rate`
  - 若共 21 项，额外包含：`v2[15]` 通算收支、`v2[16]` 通算祝仪、`v2[17..20]` 排名 `monthly_ranks[9..12]`（`通算收支`、`平均收支`、`通算祝仪`、`平均祝仪`）
- 派生量计算：
  - 对局明细：4 麻为 `p0+p1+p2+p3 = N战`，3 麻为 `p0+p1+p2 = N战`（如 `2+0+0 = 2战`）
  - 月间 `R`：取对应全期间类别的 Rate；排名取 `monthly_ranks[8]`（非 0 时追加 `N位`）
  - `通算 顺位`：3 麻为 `p0*30 - p2*30`；4 麻为 `p0*30 + p1*10 - p2*10 - p3*30`
  - `综合` 数值：普通桌在 `monthly_ranks.size() >= 9 && monthly_ranks[2] > 0` 时为 `ranks[1] + ranks[2] + ranks[3] + ranks[4]`；祝仪桌在 `monthly_ranks.size() >= 13 && monthly_ranks[10] > 0` 时为 `ranks[9] + ranks[10] + ranks[11] + ranks[12]`；排名取 `monthly_ranks[0]`
- 14 项布局与 `2x2` 黑点标记（`0x0042d970–0x0042d99d`）：
  - 顶行两块：左侧战绩计数（`335..450`）与右侧 `Rxxxx xxxx位`（`460..555`）
  - 居中灰字表头：`通算`（左列）、`平均`（右列）
  - 四行主表：`得点`、`顺位`、`收支`、`祝仪`，分别在左侧绘制通算值+排名、右侧绘制平均值+排名；非琥珀桌灰显 `收支`/`祝仪`
  - 综合行：横跨两列，左侧 `・综合` 标签，右侧综合值与排名
  - 底部两行：`一位率`（左）与 `连对率`（右，3 麻灰显）、`末位率`（左）
  - 计入综合项的标签左侧绘制 `2x2` 黑色实心方块（普通桌为 `得点`、`顺位`、`综合`；琥珀桌为 `收支`、`祝仪`、`综合`）

## 2. 重复登录与 `<ERR>` 错误弹窗

- 证据位置：`tenhou.exe.c:63731–63735`、`tenhou.exe.c:63959–64319`
- 服务端行为：
  - 官方服务器在同一账号已登录时返回 `<ERR code="1004" />`（原版日文：`このプレーヤは既に接続済みです`）。
  - 自建 `Tenhou.Server`（`Tenhou.Server/src/Application/Platform.cs:200, 235`）在同一注册账号已登录时返回 `<ERR code="400" text="该账号已在其他窗口登录" />`。
- 原版客户端处理流程：
  - 协议分发层通过 `PostMessageA(main_hwnd, 0x8202, code, ...)` 投递错误到主窗口消息队列，避免在套接字回调栈内直接阻塞重入。
  - 主窗口收到 `0x8202` 后弹出模态 `MessageBoxA(hwnd, message, caption, MB_OK)`：默认标题为 `"Error"`（`1012`/`1027` 为特殊提示标题）。
  - 致命错误码（如登录阶段或 `1001..1005`、`1014` 等导致连接不可继续的错误）弹出后通过 `GOWELCOMEBYERR` 退回登录欢迎页；非致命大厅提示（如 `1019`、`1021` 等已在登录态收到的操作拒绝）仅弹窗提示而不主动断开大厅连接。
- 重建端实现：
  - `FormatServerError(int code, const std::string &wire_text)` 覆盖官方错误码 `0`、`1001..1028`、`2000..2004` 及默认 `ERR=<code>`，自建服优先展示服务端 `text`。
  - `LobbySnapshot` 通过单调递增的 `server_error_receipt` 将 `<ERR>` 事件通知到 `Application`，主窗口经 `WM_APP + 28` 异步弹出模态 `MessageBoxW`（避免重入），并在致命错误且位于大厅时切回 `"welcome"` 视图。

## 3. 主窗口无顶栏菜单与拖拽打开牌谱

- 证据位置：
  - `tenhou.exe.c:61718`：`CreateWindowExA(..., (HMENU)0, ...)` 创建主窗口，顶部不存在 Win32 菜单栏。
  - `tenhou.exe.c:63955`：主窗口启用 `DragAcceptFiles(hwnd, TRUE)` 支持直接拖入牌谱文件。
- 重建端调整：
  - 移除此前重建期新增的顶部菜单栏 `client_menu_`（`设置... | 打开牌谱... | 返回登录`），主窗口创建与 DPI 尺寸计算统一按 `bMenu = FALSE` 处理，与原版无菜单栏壳层一致。
  - 主窗口开启 `DragAcceptFiles(window_, TRUE)` 并在非联机大厅视图处理 `WM_DROPFILES` 载入牌谱。
  - 离线牌谱视图 `TableView` 新增 `返回` 按钮（`kBack = 3118`），保证无顶栏菜单时仍可退出牌谱页返回登录页。

## 4. 登录 ID 退出后持久化记忆

- 证据位置：`tenhou.exe.c:110564–110576`、`tenhou.exe.c:110703–110719`
- 原版行为：
  - 启动加载欢迎页时读取 `config.ini` 的 `[STATUS] UNAME`（缺省 `"NoName"`）填入 ID 输入框。
  - 点击登录按钮以及退出窗口时写回 `[STATUS] UNAME`。
- 重建端调整：
  - `WelcomeView::LoadPreferences` 读取 `[STATUS] UNAME`（默认 `NoName`）填入官方 ID 输入框 `official_id_`。
  - `WelcomeView::Save` 同时写回 `[REBUILD] WelcomeName`（自建服账号，且在开启 `HIDDENID` 遮罩时保存真实 `Identity()` 而非遮罩占位串）与 `[STATUS] UNAME`（官方 ID，自动去除首尾空白），并调用 `WritePrivateProfileStringW(nullptr, nullptr, nullptr, config)` 刷新落盘。
  - `Application::Login` 在发起连接前立即调用 `welcome_->Save(config_path_)`，`Application::SetView` 离开发登录页及 `WM_CLOSE` 关闭窗口时同样保存。

## 5. 待验证项与已知项目差异

- **待验证项**：
  1. 原版 `FUN_00433e00` 在收到新 `RANKING v2` 时的 `0x68` 定时器数字滚动动画细节尚未采集逐帧时序，当前重建端直接绘制最终数值与排名。
  2. 大会战 `RANKING rankingcs` 在右侧面板内的专属排版尚未采集实窗样本，保留现有大会入口与标准战绩路径。
  3. 原版 `[STATUS] PROF_LASTTAB` 持久键目前在重建端仍沿用 `[REBUILD] ProfileLifetime` / `[REBUILD] ProfileMonthly`，待后续统一配置键迁移计划评估。
- **项目明确差异**：
  - 界面文案按重建项目约定统一使用中文目录（`Tenhou.Client/assets/text/catalog.json`），例如 `有效期限`、`平均顺位`、`一位率`、`连对率`、`末位率`；`MessageBox` 标题按用户要求与原版保持 `"Error"`。
  - 单实例互斥锁（`Local\TenhouRebuild.Config.<hash>`）按 `--config-dir` 隔离，便于同一台机器同时运行原版与重建端或双开不同配置目录进行重复登录验证。
