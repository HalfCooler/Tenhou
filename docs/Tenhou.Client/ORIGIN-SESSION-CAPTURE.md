# 原版会话消息采集

使用 Windows 上的 Python 3.11 或更新版本。在仓库根目录安装 Frida 后，用原版启动器打开客户端，停在登录页。先启动脚本并输入 `start`，再在原版窗口登录或复现目标操作。

```powershell
python -m pip install frida==17.27.1
python -X utf8 -B .\scripts\Capture-OriginSession.py capture
```

有多个 `tenhou.exe` 时可加 `--pid 1234`，或在提示符输入 `attach 1234`。每次运行默认在 `build/origin-capture/` 建立一份新 JSONL，也可用 `--out` 指定路径。附加时核对原版 EXE 的 SHA-256，客户端更新后需要重新核对观察点。

## 记录、打标和裁剪

| 命令 | 用途 |
| --- | --- |
| `start` / `pause` | 开始或暂停记录游戏消息。标记和进程附加／退出事件仍可记录。 |
| `show` | 查看最近 20 条记录及 `#序号`。 |
| `show 12 34` | 查看序号 12 到 34，包含两端及锚定在区间内的备注。 |
| `mark 已点击预约` | 给当时最后一条事件加备注。 |
| `mark @18 已显示大会报名失败` | 把备注锚定到第 18 条事件。 |
| `export 12 34 .\build\origin-capture\contest-cut.jsonl` | 把区间和对应备注保存为新文件，保留原序号和时间。 |
| `detach` / `attach [PID]` | 切换观察进程。原版重启后，在新进程登录前重新附加并输入 `start`，继续写同一份记录。 |
| `quit` | 结束采集，解除附加。 |

采集结束后可以重新打开源文件或裁剪件。审阅时新增的备注随 `export` 写入新文件。

```powershell
python -X utf8 -B .\scripts\Capture-OriginSession.py review .\build\origin-capture\contest-cut.jsonl
```

复现场景时，记录原版窗口上的动作和结果，例如「提交报名」「出现拒绝」「断线后重启」「恢复后可以出牌」。将关键画面或牌谱另存，并在备注里写入文件名。分享前复核备注、截图及另存牌谱中的身份信息。

## 观察点和证据范围

- 原版为 Windows 版 `130/0005`。`tenhou.exe` SHA-256 为 `96164cdb63e043541c27572a22b895072a8f9a0a0ee97d877a3cb340e327ffe6`，与第 3、4 阶段一致。出站观察原版游戏套接字的 `send`，记录请求发送的消息；短写和失败额外记录请求字节数和返回值。入站观察原版完成 NUL 分帧后从 `0x415F48` 发出的 `SendMessageA(0x8209)`。`0x415F52` 用 `ESI` 表示该帧长度。记录包含本机带时区的毫秒时间、方向、序号和进程附加批次。[出站调用点](../../Tenhou.Client.Origin/tenhou/tenhou.exe.txt#L36933) · [入站调用点](../../Tenhou.Client.Origin/tenhou/tenhou.exe.txt#L37399)
- 原版进程内先按标签和字段筛选再写出。账号、认证值、玩家名、会员有效期、牌谱标识等仅记录是否存在。`CHAT` 保留房号与普通房切换命令，聊天正文省略。`LN` 保留计数向量编码，`RANK v2` 保留数字字段，牌局消息保留牌实体、分数、拔牌、副露及恢复相关数字字段。未识别的消息记为 `UNKNOWN`，读取异常记为 `gap`。
- 捕获范围是当前进程已发送或已分派的游戏消息。截图、完整牌谱和牌山实证需配合人工另外保存。`detach` 表示观察进程退出或解除附加。断线提示和恢复动作可用 `mark` 记录。

## 验证记录

- 自动化覆盖消息来源过滤、字段脱敏、发送短写、启停、带标记裁剪和源文件保留。Python 套件共 18 项通过。
- 实窗使用同一指纹的原版和隔离的 `NoName` 配置。回环夹具验证双向 `HELO`、分段到达的 `LN`、暂停后跳过后续回包、脱敏文件及带标记裁剪。早期试跑附加时原版已建立官方连接，该次访客入场观察到 `HELO / PXR / LN`。注册账号、正式对局和大会的新增样本仍待按各自场景采集。
