## 2. 规格归一化

新增 `Tenhou.Client/assets/text/catalog.json`，保存可执行的文字、样式和旧编号映射。Excel 作为设计规格；JSON 是经核对的工程数据，记录来源工作表、OriginId、规格摘要和源文件校验值。

导入工具只在主动更新规格时读取 XLSX，生成待审阅的差异。日常 CMake 构建和客户端运行直接使用已登记的数据，不要求安装 Excel、Python 或在运行时解析 XLSX。CMake 生成类型化 C++ 目录，避免业务代码各自维护一份字符串表。

建议数据分为以下几类：

- `TextDefinition`：语义键、OriginId、准确文案、样式键、特殊组合规则。
- `TextStyle`：字体、字号 pt、字距 pt、粗体、填色、描边、阴影、对齐和装饰。
- `RulePatternDefinition`：玩法、服务端匹配名称、显示文字键、缺省分值。替代当前把番型名称与 PNG AssetId 绑定的结构。
- `ImageDefinition`：仅登记真正图像及原编号，不让文字通过图片加载接口回退。

同一文案的普通/悬停状态复用文案，样式分别保存。自动操作按钮按当前实际 checked 状态选样式，不将它误当成普通 hover 按钮。OriginId 用于核查和过渡适配，迁移后的业务入口引用语义键。

## 3. 字体和绘制架构

### 字体与测量

新增 `text_renderer.hpp/.cpp`，以现有 GDI+ 为基础，提供共用的布局、测量与绘制接口。`GraphicsPath::AddString` 已用于当前描边文字，可扩展到新目录。

- 字体服务管理字体对象及其生命周期；开发阶段使用已安装字体，发布阶段支持通过 ResourceManager 从指定字体文件加载私有字体集合。字体文件的发布来源和随包使用条件在打包前落实，不自动复制系统字体进入仓库。
- 检查指定字体是否实际可用、所需粗体能否生成。对规则体字体缺少粗体的情况，用样张确定统一的加粗实现，避免各处任意替换字体或重复叠字。
- 固定文案检查全部字符的 glyph 覆盖。本次读取本机字体的 cmap，当前表内固定 Label 均有字符映射；这不替代字形观感和 GDI+ 加粗验证。
- 组合数字使用字符串排版，包含数字、空格、`飜`、`符`、`点`、`枚`、`×N`。正负号和未知文案也参与覆盖检查。本机字体未映射 U+2212「−」，实现时优先沿用现有 ASCII `-`，不无意替换成缺字字符。
- 测量与绘制共用一份布局结果，返回 advance、可见字形范围以及含描边/阴影的效果范围。不能只使用带默认 padding 的 `MeasureString` 宽高确定视觉中心。
- 字距按 pt 保存，应用于字符簇之间；兼顾代理对、组合字符和混合文字，不按 UTF-16 单个码元拆分。
- 阴影通过文字轮廓生成遮罩并在最终显示尺寸生成/缓存，透明动画对填充、描边、阴影一致应用。缓存不依赖背景色。

### 单位与缩放

以现有 1440×1080 高清画布为样式设计基准，96 DPI 下：

```text
高清设计 em 像素 = Size_pt × 96 / 72
高清设计字距像素 = Spacing_pt × 96 / 72
设备像素 = 高清设计值 × 原生布局比例 × 最终视口比例
```

例如 24 pt 为 32 设计像素、56 pt 约为 74.67 设计像素，字距 +1 pt 约为 +1.33 设计像素。SD 兼容路径遵守当前 1 / 1.4 的布局约定，实际视口比例另行计算，不能再次叠乘 1.4。

统一封装 `TextRenderContext`，明确源画布、目标物理像素范围、变换矩阵和 DPI。实际窗口为 DPI 感知的前提下，若目标尺寸已是物理像素，不能再乘一遍 DPI 因子；实现阶段检查 manifest / DPI awareness 和跨屏消息，避免操作系统再次缩放整窗。

### 最终尺寸合成

当前 `OnlineTable`、`TableView` 经 `RetainedScene` / `PaintBuffer` 在固定原生画布上绘制，再用 HALFTONE `StretchBlt` 呈现。新文字层在背景和牌桌图像缩放后，以最终设备尺寸栅格化，再与图像合成输出。

- 将需要迁移的文字生成 `SceneTextRun`，携带逻辑锚点、对齐、座位仿射变换、裁切、效果和绘制顺序。
- 保留现有图像场景与鼠标坐标映射，通过共用的视口变换定位文字；文字变大不能改变按钮点击区域或牌实体身份。
- 处理中央 HUD 的四座旋转与轻微倾斜，开局介绍、结算和动作浮字分别接入各自的实际目标尺寸。
- 扩展最终合成缓存与失效规则，覆盖文本/样式/数值、目标尺寸、DPI、变换及裁切变化。淡出、数值变更和窗口恢复时，要先还原下层画面再合成，避免描边和阴影累积。
- 按现有绘制顺序合成分层命令，不将所有文字无条件放到最后；牌与计数图形等混合内容保持原有遮挡关系。
- 测量缓存以文字、字体、字号、字距和效果参数为键；栅格缓存再包含设备比例。设置容量限制，避免计时和动态名称造成无限增长。

## 5. 具体迁移边界

### 牌桌及按钮

- `original_display.hpp/.cpp`：将 `DisplaySprite` 中的文字含义迁到文字命令；图像入口只服务 7 个图像条目及其他真实图片。替换中央风位/局数、自动选项、玩法信息和振听。
- `lobby_view.cpp`：将编号按钮选择改成动作/状态到文字样式的映射，底板仍用 440，保留按下位移和禁用态。明确区分自动选项的 checked 状态与动作按钮的 hover 状态。
- `action_captions.hpp`：事件映射到语义文字键，保留四座锚点、出现缩放、淡入淡出及事件去重；每帧以当前缩放重新绘制轮廓，动画不缩放一张固定尺寸的文字 PNG。
- `match_intro_view.cpp`：替换 403–423、463/464 等文字引用；实际目标尺寸与牌桌统一处理。
- `online_table.cpp`、`table_view.cpp`：接入最终文字层及失效区域，覆盖在线、回放和窗口恢复。

### 结算及规则映射

- `settlement_scene.hpp/.cpp`：文字项携带明确样式/文字键；已知役种和标题使用目录文案，动态数字使用文本 run。替换 `481 + id`、`552 + digit` 等图片拼接逻辑，移除以文字图片尺寸计算排版的分支。
- `settlement_view.hpp/.cpp`：统一绘制和测量，删除番型图片专用尺寸回调与绘制分支。分数动画、逐项揭示和分页由现有场景状态驱动。
- `variant_artwork.hpp/.cpp`：将 `FindPatternArtwork` 的文字映射迁到番型文字目录，花牌图片继续由图像模块管理。
- `assets/catalog.cmake` / `cmake/ClientAssets.cmake`：将“服务端名称＋缺省分值”从 PNG 声明中分离。匹配仍使用服务端名，例如 `龙七对` 对应显示 `竜七対`、`国标` 玩法使用 `国標` 标签；不以显示名反推规则或计算分数。
- 结算显示服务器提供的分项、次数和总计；保留缺省分值回退、未知名称显示、每页 14 项与两列机制。

### 资源收尾

迁移期间可以保留 OriginId 到文字定义的适配器，但不得把“先生成字体 PNG，再让所有业务继续通过 GetImage 使用”作为最终接口。

旧 DAT 内同时含有需要保留的图形资源，本轮可以继续保留原包，不要求重打包或物理剔除其中闲置文字像素。完成标准是运行时不再加载、测量或绘制这些文字记录，新增文字也无需制作 PNG。

当前用户新增的 594–705 PNG 及 XLSX / Word 编辑均作为参考保留。实施不以清空目录或删除这些文件为前置条件。完成后仅从运行清单和发布复制规则中排除文字 PNG；核对干净构建和已有输出目录的增量部署，避免历史遗留文件继续影响渲染。

表外的昵称、计时、提示与系统对话框按各自用途保留现有字体策略；与本次组合文字共用布局时接入新的测量接口。此次范围以替换表内文字资源为准，不扩展为全部系统控件的视觉重做。

## 6. 验证与验收

### 自动化检查

扩展现有 `presentation_check.cpp`、`resource_check.cpp`、`variant_check.cpp` 和 `variant_ui_check.cpp`，必要时新增文字专项检查并登记到 `Tests.cmake`。

1. 目录完整性：296 个 Text 定义、7 个 Image；无重复编号、错误继承、空文案或缺失样式；覆盖 481 修正与 Info 继承。
2. 字形和布局：固定文案 glyph 可用；近似相同的文案严格按表输出；描边/阴影效果范围计入裁切；长名称、数字与单位不会互相覆盖。比较测量结果和实际绘制范围，而不是只断言代码常量。
3. 资源解耦：在隔离资源副本中缺省、加入或损坏旧文字 PNG，文字输出仍一致；实际图形缺失/损坏仍由原资源错误机制报告。不在用户资源目录做破坏性试验。
4. 合成正确性：同状态完整重绘与缓存/局部重绘结果一致；测试 hover、倒计时、分数变化、浮字结束、窗口遮挡恢复、尺寸/DPI 变化后的缓存失效。
5. 结算：三玩法已知与未知番型、`根×N`、两列、14 项及 15 项分页、长数字、符/飜/点和多份收据；原服务器匹配名与分值语义一致。
6. 性能：对静止牌桌、持续摸打和浮字动画记录迁移前后同条件的数据。静止状态不持续创建字体/重建轮廓，动态过程缓存有界；发现持续回归先定位再固定验收阈值，不凭估计宣称性能达标。
