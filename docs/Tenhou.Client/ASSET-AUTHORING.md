# 四川与国标图片制作规范

> 2026-11-16 最新约定：以 [编号图片接入表](SPRITE-INTEGRATION.md) 为准。新增界面图使用 `images/sprites/<编号>.png`；补花复用 480，两种玩法计分均复用 562“飜”，不再制作单独“补花”或“番”单位图。下文旧制作路径及中文化建议仅保留为历史参考。

2026-11-16 更新：八花已导入；补花、当前 82 项国标番种及四川番型的可选 PNG 入口、缓存和结算分页已实现。实际路径与加载行为见 [国标客户端与图片接入](GUOBIAO.md)。下文的制作尺寸与参考仍适用。

本说明用于按原始天凤图片制作新增素材。范围为图片规范、原图参考和制作清单；不修改规则、语音或运行时加载代码。四川名称以当前实现的**血战到底**为准，不据此引入血流成河的规则或专属提示。

## 1. 从这里开始

- [制作清单.csv](asset-reference/制作清单.csv)：156 条制作/复用记录，包含拟用文件名、优先级、参考图、尺寸、当前呈现方式及备注。同一文字的按钮普通态/悬停态各占一行；清单行数不等于必须新画的图片数。
- [原图尺寸清单](asset-reference/original-display.csv)：191 张图片的 ID、已确认文字、画布尺寸、非透明区域、包内字节数和导出 PNG 字节数。未确认含义的图保留空白 Label，不猜名称。
- [按钮总览](asset-reference/buttons.png)、[动作浮字总览](asset-reference/actions.png)、[立直役种总览](asset-reference/yaku.png)：棋盘格仅用于查看透明边缘，不能画进交付素材。
- [逐张透明原图](asset-reference/sprites/)：按资源 ID 命名，例如 `473.png`、`516.png`。作为编辑器中的参考层使用。
- [来源指纹](asset-reference/source.json)：原始包 SHA-256、画布和导出数量。

先试做“补花”“确认换牌”“清七对”“一色双龙会”各一张，分别验证浮字、按钮、短番型和长番型，再批量制作。

## 2. 原图实测与字体信息的边界

源文件是 `Tenhou.Client/assets/packs/_res2.dat`，签名 `res2`，对应 **1440×1080** 原生画布。资源记录保存宽高与 BGRA 像素，不包含字体名称、字号、字距或可编辑文本。位图只能确认字形外观和可见像素范围，不能证明原字体是哪一款。

从导出图可观察到毛笔楷书风格、白色字面；动作浮字有黑色投影，按钮普通态有金色光晕，役种是较小的白色楷书。`KaiTi`（楷体）是**现有客户端动态文字使用的字体**，可作为制作起点，但不能声称与原图字体完全一致。字体缺失时部分路径会回退到通用无衬线字体。

| 类型 | 原始 ID | 精确画布尺寸 | 制作依据 |
| --- | --- | --- | --- |
| 按钮共用底板 | 440 | 140×51 | 整张 alpha=77；与文字层叠加，不重复合并背景 |
| 按钮普通文字层 | 441–449 | 140×51 | 白字配金色光晕；图形居中，保留透明边缘 |
| 按钮悬停文字层 | 450–458 | 140×51 | 白字；与普通态成对，不假设只是重新着色 |
| 动作浮字 | 473–480 | 220×72 | 白色楷书、黑色投影，整张图的中心是动画锚点 |
| 役种名称 | 481–535 | 高34，宽67–225 | 宽度随名称变化；不统一拉伸到同宽 |
| 数字与计分单位 | 552–565 | 34×34 | 552–561是0–9；562是日文“飜”，不直接当国标“番” |

实测例子：`473`（ポン）非透明区域为 `(40,3,135,67)`，`477`（ツモ）为 `(40,7,137,61)`；`482`（立直）画布69×34，可见区域61×28；`516`（清一色）画布104×34，可见区域96×32；`481`（門前清自摸和）画布202×34，可见区域193×32。

这里的非透明范围包含抗锯齿和投影，**不是字号**。CSV 中 `InkX/InkY` 是非透明区域左上角，`InkWidth/InkHeight` 是其宽高，使用 alpha>0 的像素测量。`StoredBytes` 是 DAT 中该记录的像素载荷长度；`PngBytes` 是导出的 PNG 文件大小。新图须匹配画布与视觉效果，无需匹配压缩文件的字节数。

## 3. 交付格式与建议起稿参数

统一交付无损 **32位 RGBA PNG，8位/通道，直通 alpha**，透明背景。不要带白底、棋盘格、索引色或 JPEG 压缩；不要把预乘 alpha 的 RGB 当作普通 PNG 写入，以免出现黑边。保留可编辑源文件及实际字体名、字号、字距、描边/投影参数，便于之后继续补字。

下面的字号是**制作建议**，不是从原资源提取的值；均以像素 em 表示，不是 pt。若编辑器用 pt，按其文档分辨率换算，最终以导出像素实测为准。

| 类型 | 建议起稿 | 对齐与边距 |
| --- | --- | --- |
| 番型名称 | 楷体 Regular，先从32px em试起，微调至可见字形约28–32px高 | 高34px；左对齐；左右各约3–5px透明余量；宽度实测，不能裁掉长横、撇捺或投影 |
| 两字动作浮字 | 楷体 Regular，先从64–72px em试起 | 220×72，整体居中；对照473/477调字距、白色字面与黑色投影 |
| 四字“选择完毕” | 先从46–50px em试起 | 保持220×72并留边，单独调字距；不能直接把两字字号套到四字 |
| 一至两字按钮 | 先从38–42px em试起 | 140×51，字形居中；对照441/450制作两态；底板使用原440 |
| 四字“确认换牌” | 先从28–30px em试起 | 不改变按钮大小；普通态和悬停态视觉中心一致 |

投影没有可恢复的原始参数。建议在100%像素下叠放原图与新图比较，先对齐字形高度和视觉中心，再调黑色投影/金色光晕；不要将建议值当作精确复刻结果。

客户端会把原生画布按窗口等比缩放。HUD、结算布局中的 `1.4` 是现有代码的布局比例；不要将导出的高清素材再统一乘1.4。仓库只有高清原图，本轮没有实测 SD 素材。

## 4. 按呈现用途制作

### 动作浮字与操作按钮

原图上的“吃碰杠和”实际写的是日文：`473=ポン`、`474=カン`、`475=チー`、`476=ロン`、`477=ツモ`。现有变体直接复用这些图。保留现状时无需新画；若希望中文展示，再制作“碰、杠、吃、荣和、自摸”，列为P1。

“选择完毕”和国标“补花”目前由 `ActionCaptions` 动态绘制：楷体 Regular，HD为42px em、SD为30px em，黑色3px描边，字面颜色 `#FFF8D2`。这是**当前文字回退的样式**，与原始白色投影图片不同；按原图统一风格时，使用前节的浮字建议。

浮字动画按15ms定时器推进，0–19 tick从2.5倍缩到1倍并淡入，20–59维持，60–99淡出。画图时只做一张静态图，不将动画多帧或座位方向烘焙进去。HD中心锚点按自己/下家/对家/上家为 `(720,830)`、`(1190,480)`、`(720,120)`、`(250,480)`；共用同一图，按中心定位。

四川新增按钮是“万、筒、索、确认换牌”。已有440底板，目前文字为楷体、字号约按钮显示高度的55%，普通态白色，悬停态 `#FFFF99`；若改成图片，交付正常/悬停两张透明文字层。当前按钮在HD牌桌实际占140×50布局区域，原图源文件140×51会按控件区域缩放，不能把源图高度误记成50。按下时由代码位移1像素，禁用态由黑色半透明层压暗，无需各画一套。

### 四川结算番型

清单与当前 `SichuanMatch.Score` 对齐，共**18个固定名称＋1个动态“根”系列**：

底和、清一色、七对、清七对、龙七对、清龙七对、对对和、清对、带幺九、清幺九、将对、金钩钓、清金钩钓、天和、地和、杠上花、抢杠、杠上炮。

“根×N”由服务端动态组合，建议名称图只画“根”，乘号与数量单独排版；也可制作实际用到的“根×1”至“根×4”完整图片，但后续接入必须约定匹配方式。上述名称不要擅自替换成习惯称呼，例如服务端是“对对和”“杠上花”“抢杠”，不是“碰碰胡”“杠上开花”“抢杠和”。

“查花猪、查大叫、退税”目前在盘末结算原因中组合说明，没有各自独立的演出事件，列为P2设计候选。不要把它们当成已经存在的动作图片槽，也不要画与当前规则无关的“血流继续和牌”等提示。

### 国标结算番种

完整名称直接取自 `FanCatalog.Points`，82项已逐行列在制作CSV中，其中“明暗杠”是项目目录额外列出的5番项。清单对应**本项目实现**，不声称82项全部来自某一版本官方规则。

所有名称使用服务端的简体写法。例如“九莲宝灯、十三幺、七对、碰碰和、断幺”，不能仅凭字面相近复用“九蓮宝燈、国士無双、七対子、対々和、断么九”而不核对字形。原“清一色”等完全同字的图片可作为复用候选，统一字体后再决定是否重画。

服务端同类番种可能合并成“名称×N”，例如花牌及重复刻/杠类；名称图不画固定倍数。“番”“翻”和数字独立处理：国标总数用“番”，四川当前总数用“翻”。当前结算已按规则区分“番”与“翻”，国标“番”字另有可选图片入口。

当前通用结算番型仍是楷体动态文字：设计基准16px，HD转换后22px，行距24基准像素（HD为33或34px）；最多显示14项，超过6项时用两列。34px高的原生役种图适合作为新图参考，但改为图片时仍须检查列宽、两列间距、长名称和超过14项的处理。当前已增加每页 14 项的分页与图片排版。

### 八花与其他图案

八花属于牌面图案，不能使用动作浮字或番种文字的尺寸。实体ID依次是 `136梅、137兰、138竹、139菊、140春、141夏、142秋、143冬`。已选图案来源、文件名和许可核对记录见 [交互草案第6节](VARIANT-INTERACTION.md#6-已核对的花牌资源与接入方式)。

本轮只导出 `_res2.dat` 的界面图片，**没有导出 `_obj2.dat/_obj3.dat` 的牌面、框体或阴影**，因此八花宽高在清单中明确写“待定”。制作前应先导出并量取原普通牌有效图案区域、遮罩、坐标偏移以及方向关系，再把选定八花图案放进现有框体；四座旋转、缩放、计数共用运行时逻辑。不要凭空选一个统一牌面尺寸。

现有定缺标记复用灰色赤五装饰牌，可继续使用。玩家昵称、分数、剩余牌数、盘数、说明长句继续按动态文字设计，无须枚举成图片。

## 5. 清单、拟用目录与后续接入

CSV优先级含义：P0为新增图片或其复用依赖，P1为已有日文图的中文化，P2为尚无独立呈现槽的可选设计。`Width=按文字实测` 表示固定高34px、宽度按实际内容确定；`待定` 表示先确定显示位置或牌面布局，不应据此批量绘图。

拟用路径相对未来的 `Tenhou.Client/assets/images/variants/`：

```text
actions/补花.png
buttons/确认换牌-normal.png
buttons/确认换牌-hover.png
patterns/sichuan/清七对.png
patterns/guobiao/一色双龙会.png
counters/番.png
flowers/梅.png
```

这些路径中的补花、番型、番单位和八花已登记资源入口，放入资源目录后可加载；其余按钮图片仍按下列原接入清单推进：

1. 在 `assets/catalog.cmake` 登记实际外置资源，沿用 `ResourceManager`，不覆盖或重打包原始DAT。
2. 为动作、按钮、番型建立明确的规则/名称到资源映射与PNG解码缓存；未知名称继续文字回退，动态×N与数字单独处理。文件名不能直接从任意服务端文本拼成可访问路径。
3. 在 `ActionCaptions`、`LobbyView::PaintAction`、`BuildSettlementScene/SettlementView` 接入对应图片；八花走牌面专用入口。没有图片的项目继续现有呈现。
4. 在实际窗口检查四个座位、动画放大淡出、按钮两态和禁用态、结算两列与长文本；新增国标番种超过14项时一并处理现有显示容量限制。

## 6. 重新导出与交付检查

Windows / PowerShell 7.2+，不需要编译客户端，不需要安装图片编辑库。在仓库根目录运行：

```powershell
pwsh -File ./scripts/Export-DisplayReferences.ps1
# 也可指定其他输出位置，避免覆盖自己制作的文件：
pwsh -File ./scripts/Export-DisplayReferences.ps1 -OutputDirectory ./build/asset-reference
```

脚本只读取原始资源包与番型名称代码；写入指定输出目录中的原图PNG、三张总览、来源记录和两份CSV，不更改资源包或生产代码。默认输出目录仅保存参考材料，手工制作文件应另存；重新导出会更新同名参考文件。制作清单中的四川名称清单由脚本维护，国标名称按当前目录提取；规则增加名称后须同步检查四川清单。

交付时逐项核对：PNG带透明通道，画布尺寸正确，100%像素无切边，普通/悬停视觉中心一致，长番型能容纳，文字严格匹配服务端名称，源文件记录实际使用的字体和效果参数。压缩后的文件字节数可以与原图不同。
